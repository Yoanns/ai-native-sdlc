# The mirror

This directory holds the content that exists only in the agent-agnostic mirror,
[agent-native-sdlc](https://github.com/yoanns/agent-native-sdlc). Nothing in it
is part of the Claude Code plugin.

The mirror is generated by `scripts/build_mirror.py` and never edited by hand.
It is built from three things:

| Source | Becomes | How |
|---|---|---|
| `skills/`, `agents/`, `templates/REVIEW.md`, `spec.md`, `plan.md` | `playbook/`, `templates/` | Rewritten from Claude Code's vocabulary by the `PHRASES` table in the build script |
| `templates/hooks/scripts/`, `templates/enforcement/`, `LICENSE`, `SOURCES.md` | `guards/`, `enforcement/`, … | Copied byte for byte — already agent-neutral |
| `mirror/overlay/` (this directory) | the same paths in the mirror | Copied; `*.tmpl` files are rendered first |

`mirror/lifecycle-block.md` is the lifecycle section installed into every
target repository's `AGENTS.md`; the build fills in its stage table from the
orchestrator skill and the stage map.

## Changing it

- **A stage, a reference, a review pass:** edit the skill or agent here as
  usual. The mirror picks it up on the next build.
- **Something only the mirror has** — its README, setup guide, adapter configs,
  installer: edit it under `mirror/overlay/`.
- **A new Claude-specific term in a skill:** the build fails on it. Add a rule
  to `PHRASES` that says the same thing for any agent, or — if the line
  legitimately names Claude Code — an entry in `ALLOWED`.

```bash
python3 scripts/build_mirror.py --out build/mirror   # build and check
python3 scripts/test_mirror.py                       # guards, gate, installer
```

## Publishing

On every push to `main`, `.github/workflows/mirror.yml` runs the tests,
rebuilds the mirror, and pushes it to agent-native-sdlc if anything changed —
one commit per source commit, named after it, and a `v<version>` tag when the
plugin version is new. It never runs if the tests fail.

It needs write access to the mirror repository, granted once:

1. Create the repository `yoanns/agent-native-sdlc` on GitHub — empty, no
   README, licence or `.gitignore`.
2. Generate a key pair with no passphrase — press Enter twice when asked for
   one:
   ```bash
   ssh-keygen -t ed25519 -C "ai-native-sdlc mirror" -f mirror_key
   ```
   Do not pass `-N ""` from Windows PowerShell: it drops the empty argument,
   so `ssh-keygen` takes the next word as the passphrase and CI cannot use the
   key.
3. In **agent-native-sdlc** → Settings → Deploy keys → Add deploy key: paste
   the **public** key, `mirror_key.pub` — one line starting `ssh-ed25519` —
   and tick **Allow write access**. In PowerShell:
   `Get-Content mirror_key.pub | Set-Clipboard`
4. In **ai-native-sdlc** → Settings → Secrets and variables → Actions → New
   repository secret: name `MIRROR_DEPLOY_KEY`, value the **private** key,
   `mirror_key` — from `-----BEGIN OPENSSH PRIVATE KEY-----` to the END line.
   In PowerShell: `Get-Content mirror_key -Raw | Set-Clipboard`
5. Delete both key files from your machine. Run the workflow once from the
   Actions tab, or push to `main`.

Until the secret exists, the workflow still tests and builds the mirror and
reports a warning instead of publishing. A deploy key grants access to that
one repository only, which is why it is used rather than a personal token.
